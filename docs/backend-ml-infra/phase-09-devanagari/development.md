# Phase 09 local development and rollback

Run all commands from the repository root. The Python 3.12 environment and lock are the checked-in project versions. Do not replace the PostgreSQL acceptance path with SQLite.

## Local checks

```sh
npm test
npm run typecheck
npm run lint
npm run contracts:check
npm run build
make lint
.venv/bin/python -m research.schemas --check
.venv/bin/python -m research.validate
```

For database-backed Phase 09 checks, set `TEST_DATABASE_URL` to the disposable local PostgreSQL test database, then run:

The 11-case engineering fixture trace is generated by `scripts.deva_fixture` and `penforge_font_engine.shaping.shaping_suite`; the saved result is `artifacts/phase09/shaping-fixture.json`. Font runs in `artifacts/phase09/fonts-run-01` must keep the pinned OFL reference-font role and the experimental warnings. Printable page renders and visual source files live in `artifacts/phase09/templates/`.

`.venv/bin/python scripts/phase09_local_acceptance.py initialize` and `seed` prepare only the dedicated `phase09_browser_synthetic_20261020` schema, local auth-emulator identity and Noto engineering fixtures. `worker` runs a local network-denied worker. These commands are for synthetic local acceptance; do not point them at user data or a hosted service.

## Rollback

Turn off Devanagari capability for new projects/jobs and stop the local acceptance worker. Preserve already approved source/revision/snapshot/export lineage. Do not downgrade migration `0012_devanagari` when a project still pins the Devanagari set; the migration rejects that destructive downgrade. When allowed, migration rollback removes only its project script field and Devanagari-only evidence. Existing Latin projects, captures, Phase 08 style profiles and exports remain intact.
