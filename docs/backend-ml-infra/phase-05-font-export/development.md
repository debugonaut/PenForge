# Local font export development

This phase runs locally with PostgreSQL, existing Firebase identity/capture services
and the private filesystem adapter. It provisions nothing. First follow
[Phase 04 development](../phase-04-extraction-review/development.md) for authentication,
PostgreSQL, storage and approved canonical revisions.

```sh
uv sync --locked --group dev --group worker --group research
export PYTHONPATH=apps/api:packages/contracts:packages/font-engine:.
make migrate
make api
# In another shell with the same DB/storage/HMAC configuration:
make worker
npm run dev
```

The release requires migration `0008_font_exports`. It adds four nullable export
columns and publication guards; previous-release data remains readable. Empty-schema
up/down/up is supported. Downgrade refuses once a frozen Phase 05 export exists, to
preserve its build identity and lineage. Never downgrade a live database as rollback.
Stop new builds or roll forward instead; old ready fonts remain immutable.

Configure owner AND global `quota_balances` for `storage_bytes`, `exports` and
`compute_seconds`. Missing configuration fails closed. Each requested format reserves
one export, 2 MiB for font plus 512 KiB for report, and a 60-second per-attempt compile/
validation ceiling multiplied by the configured attempt limit. These provisional local
safety caps are not measured hosting capacity or ETA. Storage settles actual bytes;
ready exports settle one each; measured execution time settles compute. A killed
attempt has unknown resource use rather than an invented measurement. Limits and
reservation expiry do not justify weakening validation or altering handwriting.

Use `POST /api/v1/projects/{id}/exports` with `Idempotency-Key`, formats and family.
An optional owned immutable snapshot pins a previous milestone; otherwise the request
atomically freezes an export snapshot. `GET /api/v1/exports/{id}` returns real stages,
units, coverage and validation. `GET /api/v1/exports/{id}/download-url` authorizes a
short-lived capability. Owner IDs, private filenames and source content never become
object key prefixes; export objects use opaque asset UUIDs. Workers cannot reactivate
old exports.

In the current studio, explicitly connect private storage, select the cloud project
and open **Private font export**. Review/approval remains a separate private panel.
The local demo export remains a demo. Ready files can download or open Writing Desk;
there, **Load private generated font** fetches and verifies bytes before FontFace.
The selected font is embedded by the same real SVG/PNG renderer. Imported fonts,
Caveat samples and generated Penforge fonts have distinct labels. Generated bytes are
held in the tab, not migrated into local drafts or training data. Restricted embedding
builds cannot be loaded for document embedding through this generated-font path.

```sh
make contracts-check
make lint
npm test
# Set TEST_DATABASE_URL to a disposable real PostgreSQL database:
make test-integration
PYTHONPATH=apps/api:packages/contracts:packages/font-engine:. \
  .venv/bin/python scripts/measure_font_exports.py
npm run typecheck
npm run lint
npm run build
npm start
```

`measure_font_exports.py` retains synthetic TTF/CFF OTF/WOFF2, manifests, checksums,
shaping output, FontBakery/OTS results and renders under `artifacts/phase05-fonts/`.
Two isolated runs per fixture/format compare exact bytes. Hardware/wall/RSS are recorded;
no cloud cost, capacity, ETA or handwriting quality follows from those numbers.

For a disposable browser fixture, `scripts/phase05_local_acceptance.py initialize`
uses the specifically named local test schema. Its API factory runs on dedicated
loopback port 8005 with the explicit local Auth emulator environment; `seed` populates
the connected test guest with synthetic approved geometry; `worker` handles its
exports. Do not point this helper at real writing. Concurrent Next servers may set
`PENFORGE_NEXT_DIST_DIR=.next-dev-phase05` to avoid sharing output. Defaults remain
`.next-dev` for development and `.next` for production.

The [evidence](evidence.md) distinguishes executed checks, prior deferred browser work,
and hosted/privacy/research gates. Phase 06 needs separate authorization.
